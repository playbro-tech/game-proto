# Сообщения режима гифтов

English source: [English](../en/gift-mode.md).

Пакет экспортирует `GiftModeRequestSchema`, `GiftModeResponseSchema` и
`CommandType.gift_mode`. Они описывают явный выбор режима гифтов отдельно от
команды `play`, выполняющей раунд. Схемы поддерживают локальную интеграцию
и моки; они не подтверждают развёртывание или принятие конкретным сервером.

## Запрос и подтверждение

Запрос использует `command`, `session_id`, `sign_key` и `paused`. JSON-примеры
используют proto-имена; параметры преобразования описаны в
[сериализации](serialization.md):

```json
{
  "command": "gift_mode",
  "session_id": "test-session",
  "sign_key": "test-sign",
  "paused": false
}
```

`paused: false` выбирает гифты; `paused: true` выбирает игру на баланс.
Оба значения явно задают намерение смены режима. Запрос не содержит действия
спина. ID запросов, корреляция команды и статус ошибки принадлежат транспортной
оболочке, как и для остальных базовых сообщений запросов/ответов пакета.

Успешное подтверждение содержит оффер на верхнем уровне:

```json
{
  "gift_spin": {
    "bet": "10",
    "left": 7,
    "total": 10,
    "total_bet": "30",
    "total_win": "120",
    "status": "started",
    "paused": false
  }
}
```

Схемы используют строки int64 protobuf JSON для ставок и выигрышей;
сгенерированные сообщения TypeScript используют `bigint`. Приложения могут
отдельно применять принятые в их транспорте числовые соглашения.

## Наличие полей, контейнеры и жизненный цикл

`GiftModeRequest.paused` и `GiftSpin.paused` сохраняют наличие поля. Отсутствующее
значение представлено как `undefined` в сгенерированном TypeScript, а явное
`false` сохраняется при сериализации со стандартными настройками JSON protobuf.
Вызывающий код проверяет, что запрос содержит намерение, а успешное
подтверждение — ожидаемые оффер и режим. Один лишь разбор protobuf-сообщения
не выполняет эти бизнес-проверки. Отсутствие или null оффера не означает
существующий оффер с отключённой паузой.

Одна схема `GiftSpin` используется в следующих контейнерах:

| Ответ | Расположение оффера |
| --- | --- |
| `GiftModeResponse`, `LoginResponse`, `SyncResponse` | `gift_spin` |
| `StartResponse`, `PlayResponse` | `context.gift_spin` |

Жизненный цикл оффера и выбранный режим независимы. Строка `status` может
содержать `new`, `started`, `finished`, `deleted` или старое/специфичное для
интеграции значение. Терминальный оффер может сохранять итоговые счётчики
и выигрыш; схема не очищает их и не определяет расчёт. Нулевой остаток гифтов
сам по себе не завершает связанный бонус. `is_previous_gift` сохранён с прежним
номером поля для старых/отладочных данных и помечен устаревшим; клиенты
используют подтверждённое `paused` для режима. Пакет сохраняет
`StartRequest.mode` для совместимости формата и не выполняет автоматический
переход к нему после отказа `gift_mode`.

## Генерация и проверка

Файлы `.proto` владеют контрактом. Команды генерации и проверок описаны в
[разработке](development.md). Wire-тесты проверяют presence, контейнеры ответов,
терминальные данные и неверные значения; они не проверяют координацию UI/FSM,
поведение мок-сервера или реальное развёртывание. Окружающие команды сессии
описаны в [базовом API](base-api.md), точные поля — в
[справочнике схем](schema-reference.md).
