# Разработка схем и сгенерированная документация

Канонический источник: [English](../en/development.md).

## Исходники и prerequisites

Редактируйте `.proto` в `proto/`. Buf использует v2 module, зависимость Google
APIs, lint `STANDARD` и breaking-правила `FILE`. Сгенерированный TypeScript
не является владельцем контракта. Пакет использует pnpm `10.12.1`; диапазон
Node engines в манифесте не указан. Vite 7 и установленные инструменты требуют
совместимый современный Node runtime. Существующий `.npmrc` задаёт реестры;
не помещайте аутентификацию в документацию и генерируемые файлы.

Установите зависимости по lockfile из корня репозитория:

```bash
pnpm install --frozen-lockfile
```

## Генерация

`pnpm proto:generate` сначала выполняет `clean`, удаляя **весь `src/`**, затем
вызывает `buf generate`. Не храните там рукописные файлы. `buf.gen.yaml`
настраивает три локальных плагина:

1. `protoc-gen-es` генерирует TypeScript-сообщения, enum, дескрипторы файлов и
   сервиса в `src/`, включая импортированные схемы, с `target=ts`.
2. `plugins/gen-entry.ts` экспортирует сгенерированный `_pb`-модуль каждого
   выбранного файла через `src/index.ts`.
3. `plugins/protoc-gen-openapi.ts` записывает `dynamic/openapi.yaml` через
   собственные OpenAPI builder/mapper.

`pnpm proto:build` выполняет генерацию, затем сборку Vite и `vite-plugin-dts`.
`pnpm build` делегирует ему. Результат в `dist/` — ES-модуль, объединённые
декларации и source maps; `@bufbuild/protobuf` остаётся external. Только `dist/`
выбран в списке `files` манифеста пакета.

## Команды и проверки

| Команда | Действие |
| --- | --- |
| `pnpm proto:format` | Перезапись форматирования `.proto` через Buf |
| `pnpm proto:dep-update` | Обновление lock зависимостей Buf; результат требует review |
| `pnpm proto:lint` / `pnpm lint` | Buf lint |
| `pnpm proto:generate` | Замена сгенерированных исходников и генерация OpenAPI |
| `pnpm test` | Генерация, запуск `tests/*.test.ts` через tsx, затем Buf lint |
| `pnpm build` | Генерация и сборка пакета/деклараций |
| `pnpm docs:lint` | Валидация `dynamic/openapi.yaml` через Redocly |
| `pnpm docs:build` | Redocly HTML в `dist/docs/index.html` |
| `pnpm docs:preview` | Сборка Redocly HTML и открытие командой `open` хоста |

Для изменения схемы выполните `pnpm test` и `pnpm build`. Перед
`pnpm docs:lint` или `pnpm docs:build` выполните генерацию: Redocly-скрипты не
создают вход сами. Если нужны оба результата, собирайте пакет до Redocly,
поскольку сборка пакета может заменить `dist/`.

Текущие тесты проверяют номера enum gift mode, optional presence, JSON/binary
round trips, контейнеры ответов, терминальные счётчики и недопустимые boolean.
Их успех не означает полного покрытия всех сообщений или deployment работающего
сервера. Для изменений схем добавляйте соответствующие wire-тесты. Конфигурация
breaking-правил Buf сама не запускает сравнение с baseline; скрипта
`proto:breaking` нет. Для оценки wire-совместимости явно сравнивайте с нужной
выпущенной схемой.

## Поведение и ограничения OpenAPI

`redocly.yaml` выбирает `dynamic/openapi.yaml`, а не отслеживаемый
`docs/openapi.yaml`. Генерируемый документ использует OpenAPI 3.1, заголовок
`Game API`, версию `1.0.0` и URL сервера из `plugins/openapi/config.ts`.
Эта версия метаданных независима от версии npm-пакета; указанный хост не
доказывает доступность и совместимость и не выбирается приложением в runtime.

Mapper использует proto-имена полей, имена enum, string/int64 для 64-битных
целых, object map, массивы и oneof alternatives. Он распознаёт отдельные
well-known types, включая Struct. Выводятся комментарии методов, но не полный
семантический справочник полей и не все бизнес-обязательные поля. Компоненты
индексируются коротким именем сообщения, а не полным; коллизии имён могут
перезаписывать друг друга. В документ попадают только типы, достижимые от
аннотированных методов. Проверяйте результат при изменениях сервисов и типов;
этот вывод не является заменой protobuf-дескрипторов и полного справочника без
потерь информации.

## Совместимость и сопровождение документации

При сохранении совместимости сохраняйте номера полей, скалярные wire-типы,
номера enum и семантику presence. Резервируйте удалённые номера/имена полей
вместо повторного использования. Binary-совместимое изменение может менять
JSON-имена, TypeScript-свойства, oneof cases и поведение приложения; проверяйте
все используемые представления и установленные версии потребителей.

Поддерживайте согласованные EN/RU страницы и обновляйте
[справочник схем](schema-reference.md) по всем дескрипторам проекта: поля,
номера, optional/oneof, deprecated, значения enum и RPC-сигнатуры. Не выдавайте
импортированные Google types за API проекта. Здесь описывается текущий контракт;
при реальном переходе версий выносите миграцию в отдельное руководство.
Сохраняйте опубликованную историю changelog. Операционная точка входа —
[AGENTS.md](../../AGENTS.md).

Разработка исходников ведётся в GitHub `main` или назначенной task-ветке от
него. GitLab `master` — слой зеркала релиза. GitHub workflows делегируют тесты
и validation для PR, подготовку релиза для `main`, публикацию пакета и Redocly
docs для опубликованного релиза. Редактирование документации само не публикует
пакет и не синхронизирует зеркало. Сайт документации workspace отдельно выбирает
эти Markdown-исходники; сгенерированные копии сайта здесь не редактируются.
